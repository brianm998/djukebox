# s1275: replaced client's local player is stopped and freed (task #1313)

## The leak

`TrackFetcher.queues` owns the local `AsyncAudioPlayer`, which led back to the
fetcher two ways: its own `fetcher` property, and `history.trackFetcher`. Both
back references are now `weak`.

## Retiring a client

`ServerBrowser` calls `Client.shutdown()` on the connected client before building
its replacement. It cancels the refresh loop, closes the stream, drops any
not-yet-restored saved state, pauses and clears the local player and, on iOS,
releases its `NowPlayingCoordinator`. The server's queue is not touched. Never
call it on a `copy()`.

macOS browse windows now rebuild when the connected client object changes, so a
reconnect to the same URL does not leave them on the stopped player.

The player's seek retry now gives up when the queue is empty; it could otherwise
repeat forever and keep a stopped player alive.

## Verification

`swift build` (macOS) and an iOS simulator build of the package, plus code
reading. `DJukeboxClient` has no test target, and deallocation was not observed
at runtime.
