# s1292: AsyncAudioPlayer test fixture keeps its TrackFetcher alive (task #1321)

`AsyncAudioPlayer.fetcher` and `HistoryFetcher.trackFetcher` are weak, because
in the app `TrackFetcher.queues` owns the player. The test fixture created a
fetcher that nothing else retained, so it was gone when `makePlayer` returned and
every track lookup found nothing. `makePlayer` now returns the fetcher too, and
each test holds it with `withExtendedLifetime`. Production code is unchanged.
