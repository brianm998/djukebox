# s1277: release_github.sh and release/<version> tags (task #1307)

Releases now start with `./release_github.sh`; `release.yml` runs on
`release/*` tags. See [decision 1267](../decisions/1267-release-tags.md).

## Verification

`scripts/exit/s1277.sh` checks the workflow's trigger, tag check, tag output and
publish gate, and that the script refuses an argument.

**The tag and push path has not been run.** A trial against a scratch bare
origin was denied in the development session, which may not run `git push`. By
reading the script (version `X.Y.Z`, tag `release/X.Y.Z`):

| Situation | What happens |
| --- | --- |
| Any argument | Error naming the version constant; exits 1 before any git command |
| Tag exists locally | `rev-parse --verify` succeeds; exits 1 |
| Tag exists on origin only | `ls-remote --exit-code` returns 0; exits 1 |
| Tag free | `ls-remote` returns 2; `git tag -a` at HEAD, then `git push origin refs/tags/release/X.Y.Z` |
| Second run after success | Stops at the local-tag check |
| Origin unreachable | `ls-remote` returns another code; warns, tags, tries the push |
| Push fails | Deletes the local tag; exits 1 |

Uncommitted or untracked files, and a HEAD on no remote branch, only warn.
