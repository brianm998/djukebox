# s1271: dead-code scan and the old TODO file (task #1310)

## The scan

`scripts/periphery-scan.sh` (needs `brew install periphery`) builds the three
packages and both app schemes, then runs one Periphery scan over all of their
index stores. A package declaration therefore counts as used if either app or
the server uses it, and `#if os(...)` code is judged by the build that compiles
it. The first run builds the server's dependencies and takes 20 minutes or more.
`--strict` makes any finding fail the run.

Two things the script works around:

- Both apps are products named `DJukebox`, so it overrides
  `PRODUCT_MODULE_NAME` with the target name to keep their modules apart.
- It sets `SYMROOT` and `OBJROOT`, because an Xcode "custom build location"
  setting otherwise reuses old build output, which produces no index.

## Kept on purpose

Each is configured in `.periphery.yml` or marked in the source, with its reason.

| Kept | Reason |
| --- | --- |
| `LinuxAudioPlayer.swift` | Only referenced under `#if os(Linux)` |
| `logging/Log.swift` | Logger API: the same overloads for every level |
| Codable and Vapor `Content` properties | Read by encoders and decoders |
| `PairingClient?`, `ServiceAdvertiser?`, `NetService?`, `Thread?` properties | Assigned to keep the object alive |
| `artistTearOut` / `albumTearOut` parameters off macOS | No-ops with the macOS signature |
| `sender` on two menu actions | Target/action signature |
| SwiftUI previews, Objective-C and storyboard members | Used by Xcode or the runtime |
| "Redundant public" advice | Access level, not dead code (switched off) |

A Linux build was not run. The `Dockerfile` still uses Swift 5.2, which cannot
build a tools-version 6.0 package.
